- A field whose number changed, or a field number or name that a different field used in the base version or that a reserved statement lists: data written by one version is misread by the other.
- A type or label change on an existing field. Only these keep the binary wire format, and an old reader still truncates values out of its range: among int32, uint32, int64, uint64, and bool; sint32 and sint64; fixed32 and sfixed32; fixed64 and sfixed64; string to bytes; an enum and an integer type. Of these, only int32 and uint32, int64 and uint64, and the fixed and sfixed pairs also keep JSON. Repeated to singular loses data. Adding or removing optional, required, or a oneof around a field changes its presence and its generated code.
- A renamed field or enum value, or a changed json_name: the binary wire format is unaffected, but ProtoJSON, text format, and FieldMask paths break.
- A new enum whose zero value is not <ENUM>_UNSPECIFIED or has a business meaning, or an enum whose zero value changes, which changes what unset means.
- A service or RPC removed or renamed, or an RPC's request type, response type, or streaming changed: each breaks existing clients. A changed package or language option moves generated imports and Any type URLs.
- A meaning change with no structural one: a changed default, a comment that changes a field's unit, format, or meaning, an existing field made REQUIRED, IMMUTABLE, or OUTPUT_ONLY, a tightened protovalidate or PGV rule, pagination added to an existing RPC, or a changed google.api.http binding.
- A new RPC whose shape is cheap to fix only now: no dedicated request and response messages (google.protobuf.Empty or a wrapper type instead), a List RPC without page_size, page_token, and next_page_token, an Update RPC without update_mask, or a mutation that clients retry without request_id. Report these as "suggestion" unless the file's other RPCs already follow the pattern.
A break on a message reachable from a service RPC or serialized by code is type "issue", category "compatibility", severity "major", or "blocker" when the message is persisted (a database, cache, queue, or event log). A break that affects only JSON, text format, or generated source needs the evidence the protobuf rule above asks for. In an alpha package (v1alpha1) breaks are allowed, so report them as "note"; in a beta package, say that a removal needs a deprecation period first. A removed field or enum value left unreserved, or a deleted reserved entry, belongs to the separate schema-evolution hygiene check; report it here only when a number or name is actually reused.
