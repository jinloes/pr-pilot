- A switch, when, or match over a protobuf enum read from another process with no default branch: enums are open, so a newer writer's value arrives as an unknown number. In Java, getNumber() throws on UNRECOGNIZED; use the field's Value getter.
- A protobuf enum read from one message or service and passed to another message's setter or builder: in Java the setter throws IllegalArgumentException on UNRECOGNIZED, failing the whole response (often inside a future). Skip UNRECOGNIZED, or copy the number with the Value setter.
- A Java or Kotlin message getter compared with null: getters return a default instance, never null; use hasX().
- A partial update applied by merging, or by replacing the stored message, without a FieldMask: an implicit-presence field cannot be set to zero, empty, or false that way, and merging appends to repeated fields instead of replacing them.
- Serialized message bytes used as a cache key, hash, signature input, ETag, or equality check: serialization is not canonical across versions, languages, or map order. In Go, reflect.DeepEqual or == on messages is wrong too (use proto.Equal), as are copying a message by value and encoding one with encoding/json (use protojson).
- At a JSON boundary: a parser that rejects unknown fields (JsonFormat.parser() without ignoringUnknownFields(), json_format.Parse without ignore_unknown_fields) on data from another deployable, so a newer writer's new field fails the read; a message relayed through JSON or a field-by-field copy, which drops unknown fields; or an int64 read as a JSON number, although ProtoJSON writes it as a string.
- A gRPC call with no deadline or context timeout (gRPC sets none by default); a handler that calls downstream with a fresh context instead of the incoming one, losing its deadline and cancellation; or a channel created per request.
- A gRPC handler that returns validation failures as UNKNOWN or INTERNAL instead of INVALID_ARGUMENT, passes a downstream error status straight to its own caller, or returns NOT_FOUND before checking permission, which leaks existence.
- REQUIRED field_behavior, protovalidate, or PGV annotations relied on with no validator or interceptor on the server path (annotations validate nothing on their own), or an OUTPUT_ONLY field accepted from the client and stored.
- From untrusted input: an Any unpacked without checking its type (Python's Unpack() returns False and leaves the message empty), a raised recursion or size limit, or a page_token whose embedded filter or tenant is trusted without authorizing each page.
Report a trap the diff shows firing as type "issue"; channel reuse, keepalive tuning, and similar design advice are "suggestion".
