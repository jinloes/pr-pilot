- Untrusted text (user input, documents, web pages, tool results, repository content) placed into a prompt without marking it as data, or into the system or developer message.
- Model output used as SQL, a shell command, a file path, a URL, HTML, or code, or as tool arguments, without validation, escaping, or an allow-list.
- A tool or agent granted more than the task needs (write, network, or shell access, or broad credentials), or allowed to take destructive actions without confirmation.
- A secret, credential, or private data placed in model-visible context, logged with the prompt or response, or sent to a provider it is not approved for.
- No limit on output tokens, agent or tool-call iterations, retries, input size, or per-user cost.
- A model response parsed without handling malformed, truncated, or refused output.
- A changed prompt rule that contradicts another instruction the model receives: a shared rule set it is combined with, or guidance a tool or projection returns (a next step, a flag that says when to offer an action, a note on what never to claim). Check the empty, not-found, and unavailable cases on their own: "if it returns nothing, say nothing failed" contradicts a tool that returns an empty list with a note not to say nothing failed. Search the other prompts that include the same shared rules, unchanged ones too, for the same conflicting line and name each one.
- A grounding, policy, or fallback guard on agent turns that blocks unverified tool exits (such as a terminal answer tool) while letting a direct no-tool final response through without a successful lookup result in the turn's history; one that checks only whether a lookup tool was called while ignoring an error, not-found, or unavailable observation; or one that exempts free-form replies matching broad keywords (such as `date`, `when`, or `link` without a number), letting ungrounded factual claims without figures pass as clarification prompts.
